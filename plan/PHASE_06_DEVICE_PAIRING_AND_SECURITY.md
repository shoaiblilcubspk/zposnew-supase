# Phase 06: Ephemeral QR Device Pairing & Device Security

> **Reference:** `docs/USER & ROLE SETUP — FIRST INSTALL TO DAILY SALES.md` & `docs/RBAC_RULES.md`  
> **Mandate:** Ephemeral pairing credentials. Zero plaintext secrets in QR codes. Cryptographic device authentication and instant revocation.

---

## 1. Objectives & Scope

Implement the secure multi-terminal pairing flow. Allow secondary terminals (phones, tablets, additional desktop checkouts) to join an existing shop via ephemeral QR code exchange, receive an initial baseline snapshot bootstrap, and maintain trusted status in the local mesh network.

---

## 2. Pairing Architecture & Lifecycle

```text
Admin Terminal (PC-MAIN)                     New Terminal (PHONE-01)
       │                                                │
       │ 1. Open "Pair New Device"                      │ 2. Select "Join Existing Shop"
       │    Generate Ephemeral Token (5 min expiry)     │    Open Camera Scanner
       │    Display Pairing QR Code                     │
       │                                                │
       │◄───────────── 3. Scan QR Code ─────────────────│
       │    (Transfers: shop_id, temp_token, signal_ch) │
       │                                                │
       │ 4. Prompt Admin:                               │
       │    "Approve pairing request from PHONE-01?"    │
       │    [ Approve ] / [ Reject ]                    │
       │                                                │
       │ 5. Admin Approves                              │
       │    • Assign DEVICE_ID: PHONE-01                │
       │    • Exchange ECDSA Public Keys                │
       │    • INSERT INTO devices (trusted)             │
       │                                                │
       │ 6. Initial Baseline Snapshot Bootstrap         │
       │    (Shop, Users, Products, Customers, Balances)│
       │───────────────────────────────────────────────►│
       │                                                │
       │                                       7. Verify SHA-256 Checksum
       │                                          Commit Initial SQLite DB
       │                                          Terminal Ready for Sales
```

## 3. Ephemeral QR Token Security Rules

1. **Short-Lived:** Pairing tokens expire automatically in 300 seconds (5 minutes).
2. **Single-Use:** Once used for a successful handshake, the token is permanently invalidated.
3. **No Sensitive Data:** QR code contains ONLY `{ shop_id, token, signaling_room }`. It MUST NEVER contain:
   * Plaintext PINs or passwords
   * Admin master recovery code
   * Device private keys
4. **Explicit Admin Confirmation:** A device cannot join without explicit click confirmation on the root Admin terminal.

---

## 4. Initial Snapshot Bootstrap vs Incremental Sync

* **Bootstrap (Joining Device Only):**
  * When a newly approved device joins, it requires current baseline state.
  * The Admin device packages a compressed snapshot of:
    `shop`, `users` (with salted PIN hashes), `roles`, `products`, `categories`, `inventory_balances`, `customers`, `settings`.
  * The new device writes this baseline to its clean local SQLite database.
* **All Subsequent Sync:**
  * Once bootstrapped, the device records its initial sequence checkpoint.
  * Future sync exchanges ONLY delta events via `sync_outbox` (Phase 05).

---

## 5. Device Revocation Protocol

1. **Revocation Action:** Admin navigates to `Settings → Devices` and clicks "Revoke Device".
2. **Local Commit:** Terminal updates `devices SET status = 'revoked' WHERE id = ?`.
3. **P2P Broadcast:** Terminal emits a `DEVICE_REVOKED` outbox event.
4. **Enforcement:**
   * When peers receive `DEVICE_REVOKED`, they close any active WebRTC DataChannel with that device.
   * Any future incoming sync packets signed by that device are rejected immediately.
   * Historical sales generated by the device prior to revocation remain valid.

---

## 6. Verification & Acceptance Criteria

- [ ] Pairing QR code expires after 5 minutes.
- [ ] Scanning QR initiates an approval modal on the Admin screen.
- [ ] Approving the request exchanges ECDSA keys and assigns a unique `DEVICE_ID`.
- [ ] New device receives initial snapshot, verifies integrity, and enters POS mode.
- [ ] Revoking a device instantly terminates its P2P connection and rejects incoming sync events.
